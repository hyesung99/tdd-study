## 1. 프로젝트 개요

**프로젝트 이름**

- 스파르타 스터디 Q&A 게시판 (가제)

**목적**

- 프론트엔드 TDD 스터디를 위한 연습용 기능 구현
- 실제 서비스로 운영하지 않지만, “실 서비스 수준”의 요구사항을 가정하고 설계/개발/테스트 연습

**타깃 유저 (가정)**

- 사내 개발자/기획자/디자이너 등 로그인된 사내 구성원

**특징**

- 구현 난이도는 낮게 유지
- 단, 수평적으로 다양한 테스트 케이스가 나올 수 있도록 기능을 설계
  (입력 검증, 필터/정렬, 좋아요, 권한, 로딩/에러 상태 등)

---

## 2. 용어 정의 및 역할

**주요 용어**

- **질문글(Question)**
  - 게시판에 등록되는 1개의 글. 질문/팁/노하우 모두 포함.
- **댓글(Comment)**
  - 질문글에 대한 답변 또는 추가 의견.
- **작성자(Author)**
  - 질문글 또는 댓글을 작성한 사용자.
- **해결 여부(Resolved)**
  - 질문글이 해결되었는지 여부 (미해결 / 해결됨).
- **공개 범위(Visibility)**
  - 질문글을 누구에게 공개할지에 대한 설정.
  - 예: 전체 공개 / 팀원만 / 비공개(작성자 본인만)

**역할(Role) 가정**

- 로그인된 일반 사용자 한 종류만 존재
- 단, 다음 권한 규칙만 존재:
  - 질문글/댓글 **작성자만** 해당 질문글/댓글을 수정/삭제할 수 있다.
  - 질문글의 **해결 여부 변경은 작성자만** 가능하다.

## 3. 기능 목록

1. 질문글 목록 보기
2. 질문글 상세 보기
3. 질문글 작성
4. 질문글 수정
5. 질문글 삭제
6. 댓글 작성 및 삭제
7. 좋아요(추천) 기능
8. 목록 필터 및 정렬
9. 간단한 권한/유효성 검증 처리
10. (선택) 질문글 작성 폼 임시 저장 기능

## 4. 화면 설계

### 4.1. 질문 목록 페이지

**경로 예시**

- `/questions`

**구성 요소**

- 상단 영역
  - 페이지 제목: `스터디 Q&A`
  - 버튼: `질문 작성하기`
- 필터/정렬 영역
  - 검색 입력 필드
    - 라벨: “제목/내용 검색”
    - 기능: 제목 또는 내용에 키워드가 포함된 질문만 필터링
  - 카테고리 드롭다운
    - 옵션: `전체 / JavaScript / React / 테스트 / 기타`
  - 해결 여부 필터 (디폴트
    - 옵션: `전체 / 미해결만 / 해결됨만`
  - 정렬 옵션 (디폴트: 최신순)
    - 옵션: `최신순 / 좋아요순 / 댓글 많은 순`
- 목록 영역
  - 질문 카드(리스트 아이템) 구성:
    - 제목
    - 카테고리
    - 작성자 이름
    - 작성일 (형식은 yyyy-mm-dd 또는 상대시간 중 택1)
    - 댓글 수
    - 좋아요 수
    - 해결 여부 뱃지: `[미해결]` 또는 `[해결됨]`
- 페이징
  - 방법은 팀 내에서 선택
    - 예시 1: “이전 / 다음” 버튼
    - 예시 2: 간단한 페이지 번호
    - 예시 3: 무한 스크롤

---

### 4.2. 질문 상세 페이지

**경로 예시**

- `/questions/:id`

**구성 요소**

- 상단 정보 영역
  - 제목
  - 카테고리
  - 작성자 이름
  - 작성일
  - 해결 여부 뱃지
- 본문 영역
  - 질문 내용 (텍스트 기준, 마크다운은 스펙에서 제외하거나 선택 사항)
- 상단 우측 액션 영역
  - 좋아요 버튼 (토글)
    - 상태: 활성/비활성
    - 옆에 좋아요 수 표시
  - 해결 여부 토글 버튼
    - 작성자에게만 노출/활성
- 하단 액션 영역
  - 버튼: `수정하기` (작성자만)
  - 버튼: `삭제하기` (작성자만)
- 댓글 영역
  - 댓글 입력 영역
    - 텍스트 입력
    - 버튼: `댓글 등록`
  - 댓글 리스트
    - 각 댓글에 표시:
      - 내용
      - 작성자 이름
      - 작성일
      - (작성자인 경우) `삭제` 버튼

---

### 4.3. 질문 작성/수정 페이지

**경로 예시**

- 작성: `/questions/new`
- 수정: `/questions/:id/edit`

**입력 필드**

- 제목 (필수)
- 내용 (필수)
- 카테고리 (필수, 드롭다운)
  - 옵션: `JavaScript / React / 테스트 / 기타`
- 공개 범위 (필수, 드롭다운)
  - 옵션: `전체 공개 / 팀원만 / 비공개`
- (수정 시 선택) 해결 여부
  - 옵션: `미해결 / 해결됨` (수정 페이지에서만 표시해도 됨)

**버튼**

- `임시 저장` (선택 기능)
- 작성 모드일 때: `등록하기`, `취소`
- 수정 모드일 때: `수정 완료`, `취소`

**입력 검증 규칙**

- 제목
  - 필수, 2~50자
- 내용
  - 필수, 10~2000자
- 카테고리
  - 필수 (드롭다운 선택)
- 공개 범위
  - 필수 (드롭다운 선택)

## 5. 기능 요구사항 상세 (Given / When / Then 형태)

### 5.1. 질문글 목록

**1) 기본 목록**

- Given: 사용자가 `/questions`에 접속했을 때
- Then: 최신순으로 정렬된 질문 목록이 표시된다.
- And: 각 질문 카드에 제목, 카테고리, 작성자, 작성일, 댓글 수, 좋아요 수, 해결 여부가 표시된다.

**2) 검색**

- Given: 사용자가 검색어를 입력하고 엔터 또는 검색 버튼을 눌렀을 때
- Then: 제목 또는 내용에 검색어가 포함된 질문만 목록에 표시된다.

**3) 필터 (카테고리, 해결 여부)**

- Given: 사용자가 카테고리/해결 여부 필터를 변경했을 때
- Then: 선택된 조건을 모두 만족하는 질문만 목록에 표시된다.

**4) 정렬**

- Given: 사용자가 정렬 옵션을 `좋아요순`으로 변경했을 때
- Then: 좋아요 수가 많은 순서대로 질문이 정렬된다.

**5) 빈 상태**

- Given: 검색/필터 결과에 해당하는 질문이 하나도 없을 때
- Then: “조건에 맞는 질문이 없습니다.”라는 메시지가 표시된다.

**6) 로딩/에러 상태**

- Given: 질문 목록 데이터를 불러오는 중일 때
- Then: 로딩 스피너 또는 로딩 메시지가 표시된다.
- Given: 서버 에러 등이 발생했을 때
- Then: “목록을 불러오지 못했습니다. 다시 시도해주세요.” 메시지가 표시된다.

---

### 5.2. 질문글 상세

**1) 상세 정보 표시**

- Given: 사용자가 `/questions/:id`에 접속했을 때
- Then: 해당 질문의 제목, 카테고리, 작성자, 작성일, 내용, 해결 여부가 표시된다.

**2) 좋아요 토글**

- Given: 사용자가 아직 좋아요를 누르지 않은 상태에서 좋아요 버튼을 클릭했을 때
- Then: 좋아요 수가 1 증가하고 버튼 상태가 활성화된다.
- Given: 이미 좋아요를 누른 상태에서 다시 버튼을 클릭했을 때
- Then: 좋아요 수가 1 감소하고 버튼 상태가 비활성화된다.

**3) 해결 여부 토글 (작성자만)**

- Given: 현재 사용자 = 질문글 작성자이고 해결 여부 토글 버튼을 클릭했을 때
- Then: 해결 여부가 미해결 ↔ 해결됨으로 변경된다.
- And: 목록/상세 화면 모두에서 변경된 상태가 반영된다.

**4) 수정/삭제 버튼 노출 조건**

- Given: 현재 사용자 = 질문글 작성자일 때
- Then: 상세 페이지에 `수정하기`, `삭제하기` 버튼이 보인다.
- Given: 현재 사용자 ≠ 질문글 작성자일 때
- Then: 위 버튼들이 보이지 않는다.

---

### 5.3. 댓글 기능

**1) 댓글 작성**

- Given: 댓글 입력란에 1자 이상 텍스트를 입력한 상태에서 `댓글 등록` 버튼을 클릭했을 때
- Then: 새로운 댓글이 댓글 리스트에 추가된다.
- And: 댓글 입력란은 비워진다.

**2) 댓글 삭제 (작성자만)**

- Given: 현재 사용자 = 해당 댓글 작성자이고 `삭제` 버튼을 클릭했을 때
- Then: 삭제 확인 후, 해당 댓글이 리스트에서 제거된다.

**3) 댓글 입력 검증**

- Given: 댓글 입력란이 비어 있는 상태에서 `댓글 등록` 버튼을 클릭했을 때
- Then: “댓글 내용을 입력하세요.” 에러 메시지를 표시하고 등록을 막는다.

---

### 5.4. 질문 작성/수정

**1) 필수 입력 검증**

- Given: 제목/내용/카테고리/공개 범위 중 하나 이상 비어 있는 상태에서 `등록하기` 또는 `수정 완료` 버튼을 클릭했을 때
- Then: 각 필드별로 적절한 에러 메시지를 표시한다.
- And: 서버 요청(API 호출)은 발생하지 않는다.

**2) 길이 검증**

- Given: 제목이 2자 미만 또는 50자 초과일 때
- Then: 제목 필드 하단에 “제목은 2자 이상 50자 이하로 입력해주세요.” 메시지를 표시한다.
- Given: 내용이 10자 미만 또는 2000자 초과일 때
- Then: 내용 필드 하단에 “내용은 10자 이상 2000자 이하로 입력해주세요.” 메시지를 표시한다.

**3) 등록/수정 성공 시 동작**

- Given: 모든 입력이 유효하고 서버 응답이 성공일 때
- Then: 해당 질문의 상세 페이지로 이동하거나 “등록이 완료되었습니다.” 토스트 메시지를 보여준다.
  (구체적인 UX는 팀 내에서 선택)

**4) 수정 모드 초기값**

- Given: 사용자가 `/questions/:id/edit` 경로로 진입했을 때
- Then: 기존 질문의 제목/내용/카테고리/공개 범위/해결 여부가 폼에 미리 채워져 있다.

---

### 5.5. 질문 삭제

**1) 삭제 플로우**

- Given: 현재 사용자 = 질문글 작성자이고 `삭제하기` 버튼을 클릭했을 때
- Then: “정말 삭제하시겠습니까?” 등의 확인 모달 또는 브라우저 기본 confirm을 띄운다.
- And: 사용자가 확인을 선택하면 질문글이 삭제된 것으로 처리되고, 질문 목록 페이지로 이동한다.

**2) 권한**

- 질문글 작성자가 아닌 경우:
  - 상세 화면에 `삭제하기` 버튼이 노출되지 않는다.
  - (백엔드 가정 시) 삭제 요청을 보내더라도 실패 처리된다고 가정.

---

### 5.6. 임시 저장 (선택 기능)

**1) 임시 저장**

- Given: 사용자가 질문 작성 페이지에서 일부 내용을 입력한 뒤 `임시 저장` 버튼을 누를 때
- Then: 현재까지의 입력값을 브라우저 로컬스토리지 등에 저장한다.

**2) 임시 저장 불러오기**

- Given: 사용자가 다시 `/questions/new`에 접속했을 때, 기존 임시 저장 데이터가 존재한다면
- Then: “이전에 작성 중이던 내용이 있습니다. 불러오시겠습니까?” 메시지를 표시한다.
- And: 사용자가 확인을 선택하면, 임시 저장된 값으로 폼을 채운다.

## 6. 비기능 요구사항 (프론트 기준)

- 백엔드는 실제로 구현하지 않아도 되며, **Mock API 또는 MSW** 등을 활용해도 된다.
- 상태 관리, 라우팅, 테스트 라이브러리는 팀이 편한 스택 사용 (예: React + React Query + React Router 등).
- 본 프로젝트의 목표는 기능 완성보다는 **TDD와 테스트 코드 작성 경험**에 있다.
  - 기능 스펙이 일부 단순해져도 괜찮음
  - 대신, 다양한 케이스에 대한 테스트 작성을 목표로 한다.

## 7. TDD 관점 테스트 범위 제안

### 7.1. 유닛 테스트 대상 (예시)

- 입력 검증 유틸 함수
  - 제목/내용 길이 체크
  - 필수값 체크
- 필터/정렬 로직
  - 카테고리/해결 여부/검색어 필터 결과 검증
  - 좋아요순/댓글 많은 순 정렬 함수
- 좋아요 토글 로직
  - 현재 상태에 따라 +1 / -1 되는지 검증

---

### 7.2. 컴포넌트 테스트 대상 (예시)

- 질문 카드 컴포넌트
  - props에 따라 제목/뱃지/카테고리/댓글 수/좋아요 수가 올바르게 표시되는지
- 질문 작성 폼 컴포넌트
  - 필수 값 미입력 시 에러 메시지가 표시되는지
  - 입력값이 유효할 때만 제출 버튼이 활성화되는지(선택 사항)

---

### 7.3. 페이지(통합) 테스트 대상 (예시)

- 질문 목록 페이지
  - 검색어 입력 → 결과 필터링
  - 카테고리/해결 여부 필터 변경 → 결과 변경
  - 로딩/에러 상태 UI 노출
- 질문 상세 페이지
  - 초기 렌더링 시 질문/댓글 표시
  - 댓글 작성 → 리스트에 추가
  - 좋아요 토글 → 숫자 및 버튼 상태 변경
- 질문 작성/수정 페이지
  - 유효하지 않은 입력 → 폼 제출 차단 + 에러 메시지
  - 유효한 입력 → 성공 플로우 (상세 페이지로 이동 등)
